# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

pycommflag flags segments of a TV recording as show/commercial using per-frame video+audio features and a small Keras model. It is a drop-in replacement for MythTV's `mythcommflag`.

## Checking a change

No linter, no pytest: `tests/test_*.py` are plain scripts with a non-zero exit on failure. None needs a video or a trained model and together they take about 10 seconds, so run them all after any code change, then re-run a failing one on its own to read its output:

```sh
for t in tests/test_*.py; do venv/bin/python3 "$t" > /dev/null 2>&1 || echo "FAILED $t"; done
```

No test covers post-processing or scoring (`post_predict`, `diff_tags`, tag merging and snapping, `_split_lead_in`) or `build_model`/`train`. Check a change there with a throwaway script on made-up tags, or add a test in the same style; the end-to-end check is `--eval`.

A change to feature extraction (`player.py`, `processor.py`, `logo_finder.py`, the audio segmenter) reaches only recordings flagged after it. The videos behind hand-labelled logs get deleted, so those logs keep what the old extractor wrote, and neither retraining nor `--eval` can show what the change does. Test it on synthetic input, as the existing tests do, and say in your summary what difference it leaves between the training logs and new recordings.

`test_logo_finder.py` runs on saved logo persistence maps (see `tests/README.md`): it prefers the full-fidelity set in `tests/private/` (gitignored; **never publish it**: the maps render as readable pictures of someone's recordings) and falls back to the scrubbed `tests/fixtures/`. The source recordings get deleted over time, so add new fixtures rather than regenerating these.

## Running

Packaging is `pyproject.toml` (the source of truth for deps; extras `mythtv`, `yaml`, `all`); `requirements.txt` mirrors it with all extras for the `./run.sh` + `./venv` flow, so keep the two in sync. `pycommflag/__init__.py` deliberately imports no submodules, so tkinter/TF are only loaded by modes that need them.

```sh
./run.sh -f video.ts                 # full pipeline: extract features -> feature log -> predict -> output
./run.sh -r /tmp/cf_*.json           # re-predict from saved feature logs (no video decode); rewrites logs and output whose tags changed
./run.sh -g cf_foo.json              # tk GUI to hand-edit tags; saves back into the feature log
./run.sh -g "some title"             # no argument, or search text: pick a recording from a list (MythTV's), then edit it; also takes a video, a link to one, or <chanid>_<starttime>
./run.sh -t --data data/* TEST data/test/*   # train; files after the literal TEST token are the validation set
./run.sh --eval m1.keras m2.keras --data data/test/*   # compare models
./run.sh --no-log -o edl -f video.ts # don't keep feature log; write .edl next to video
```

All options live in `options.get_options()` as one flat argparse parser (no subparsers, for mythcommflag CLI compatibility); `options.resolve_mode` derives the mode afterwards with fixed precedence: `--rebuild`/`--queue` > `-t` > `-r` > `--eval` > `-g` > flag. `--yaml FILE` overwrites any parsed option with the YAML's keys. `--deinterlace` stores `False` into `no_deinterlace` (deinterlacing is off by default). `--batch-size` and `--diff-threshold` are parsed but read nowhere: the constants `BATCH_SIZE` and `DIFF_THRESHOLD` in `neural.py` are what count. `main.run`'s return value is the process exit code.

Flagging has side effects beyond the feature log. Where MythTV is configured, `-f`, `-r` and saving from `-g` replace the recording's break marks in its database under the default `-o auto`, whenever they can tell which recording it is (`-j`, `--chanid`/`--starttime`, the log's `chanid`, or a `<chanid>_<starttime>` file name); `-r` also rewrites the logs it is given and can move them into `old/`. To try something out, work on a copy of the log and pass `-o edl --output-dir <scratch>` (with `-f`, also `-l <scratch>/cf_x.json`).

`--data` lists may hold directories and `.npy` files (both are skipped), and a file on both sides of `TEST` only validates, which is why `data/* TEST data/test/*` works. Always give training its `TEST` files: the best epoch is picked on them and the saved model is scored on them.

Without `-l` or `--no-log`, the feature log is kept as `$TMPDIR/cf_<video basename>.json`. `-g` (`picker.py`) finds a recording's log by that name, trying both `.ts` and `.mkv`, in `--log-dir` (else `$PYCOMMFLAG_LOG_DIR` and `$TMPDIR`) and each one's `old/`. As MythTV's flagging job it is run as `pycommflag -e -j %JOBID%`. Re-running `-f` against an existing log reuses its saved logo and skips the logo search, so give it a fresh `-l` path to exercise a change to the search.

The ina_foss audio segmenter downloads its model on first use (needs network, cached in `~/.keras/inaSpeechSegmenter`). Extraction and training `os.nice()` themselves (10 and 19): they are meant to run as background jobs.

### Models

The models dir (`--models`) defaults to the checkout's `models/` (gitignored) if it exists, else `~/.keras/pycommflag`. `neural._find_model` resolves `--model`, else `model.keras`/`model.h5` there, else downloads `MODEL_URL` via `keras.utils.get_file` as `MODEL_FNAME` (into `options.user_models_dir()` if the models dir isn't writable, since `get_file` would otherwise silently use `/tmp/.keras`). An existing download is deliberately left to `get_file` so it is re-checked against `MODEL_SHA256`; `--no-download` uses it as-is. The GUI calls `raw_predict`, so it needs a model too; it can't make `INTRO`/`CREDITS` tags and counts old ones as show.

`neural._load_model` caches models by realpath+mtime (each `load_model` leaks ~5MB that `clear_session` doesn't free) and rejects any whose input shape isn't `(WINDOW_BEFORE+1+WINDOW_AFTER, FEATURE_WIDTH)`. `MODEL_FNAME` encodes that shape and `MODEL_URL` is the asset of that name in the `models` release, so after a feature/window change a new model must be uploaded under the new name and `MODEL_SHA256` updated.

Training writes `<models dir>/pycf-<acc>-<MTYPE>-<F>x<K>x<number of dilations>-<DROPOUT>-w<before>x<after>-<unix time>.keras`, only if acc >= 0.95. acc is what `--eval` would score the best epoch on the TEST files (`_score_models`, shared with `eval`; post-processed tags in seconds, not the per-window val accuracy, which only picks the epoch), so the number in a model's name is its test accuracy. No other hyperparameter is in the name: runs that differ in anything else are told apart only by the timestamp, so note which file came from which run.

## Architecture

Pipeline (orchestrated by `main.run`, which dispatches to the `_cmd_*` functions):

1. **Feature extraction** — `processor.process_video`: `Player` (PyAV wrapper, error recovery in `_Recovery`) decodes. `logo_finder.search` first samples the first hour via `Player.frames_stride`, which decodes only reference frames, or only keyframes when GOPs are short (`MAX_KEYFRAME_GAP`). It never skips packets itself and waits for a keyframe at the start and after recovery seeks, since a frame decoded without its references is garbage; only the reference→keyframe switch is safe mid-stream. The search finds a static station logo from Sobel edges in the corners. Then frames go to the `VideoProc` thread (logo present, blank, column-mean diff) and audio to the `AudioProc` thread (front/rear RMS + `extern/ina_foss` speech/music/noise, run in chunks); merged per-frame rows are streamed to the feature log. The blank test ignores the logo's box and any stuck-overlay boxes (`search` returns those through `stuck_out` even when it finds no logo; a banner up all recording otherwise stops every frame reading as blank). "Logo present" also requires few lit edges elsewhere in the box (`_LOGO_MAX_OFF_EDGES`), so a QR code or dense text over the logo doesn't count.
2. **Feature log** (`cf_<basename>.json`, optionally `.gz`) — the central data artifact, read/written by `processor.read_feature_log`/`write_feature_log`; `read_feature_spans` turns frame columns into spans. Besides metadata (`file_version`, `filename` = realpath of the video, `frame_rate`, stream start times, `logo`, …) it holds `frames` (one row per video frame: `time, logo_present, is_blank, diff, fvol, rvol, silence, speech, music, noise`, then `cc_text`, the CEA-608 caption characters: logged for a future dataset, not a model input) and `tags` (list of `(SceneType value, (start_sec, end_sec))`), which are both the prediction output and the hand-curated training labels. `edited` is when the GUI last saved it; `processor.set_header_key` puts it right after `filename` so the picker can read it from the file's first 4KB.
   Audio is timed from the *video* start (`Player._queue_audio`). Older logs timed it from the audio stream's start, making every audio column late by 0.2–1s; a log *without* an `audio_shift` key still is. `tools/upgrade_log.py` repairs old logs: audio shift, `cc_text` from the caption bytes in the video's (or `.mkv`'s) packets without decoding, and `mkv_lag`; each step skips what the log already has. The GUI flags a log missing `audio_shift` or `cc_text` and prints the upgrade command.
3. **Model input** — `neural.load_nonpersistent` turns frame rows into a float matrix. Columns are the module constants at the top of `neural.py`:
   - 0–9 (`NORMTIME`…`NOISE`): the raw frame columns (any after these are dropped), except that `FVOL`/`RVOL` are rescaled by the recording's median non-silent front volume (`HAVE_RVOL` is decided before the rescale) and `DIFF` is /40 clipped to 1;
   - 10–15 (`LOGO_RUN`, `HAVE_LOGO`, `HAVE_RVOL`, `PERCTIME`, `BLANK_SINCE`, `BLANK_UNTIL`): derived per-frame; the three distances go through `_scale_dist` (capped at `DIST_CAP`, log-scaled), and before the first logo frame `LOGO_RUN` reads as capped, not 0;
   - 16–19 (`GENERATED_FEATURES_START`…`DIFF_MAX`): summary stats added by `condense` when it downsamples to `SUMMARY_RATE` (1/sec). It bins frames by timestamp, not count, and LOGO_RUN, blank distances and the boundary upweight are measured from timestamps too: soft-pulldown film decodes to ~24 unevenly spaced frames a second on a 29.97 channel, so counting frames is ~20% short there;
   - 20–22 (`TIMESTAMPS`, `ANSWERS`, `WEIGHTS`): bookkeeping, not model input. `FEATURE_WIDTH` = 20 is the model's input width.

   The condensed array is padded by repeating the first/last row, and `load_data_sliding_window` produces one window of `WINDOW_BEFORE + 1 + WINDOW_AFTER` (121) seconds per output second; logs shorter than two windows yield `None`.

   Training labels/weights: `INTRO`/`TRANSITION`/`CREDITS` tags are dropped first, so they train as plain show. Same-type tags under `TAG_MERGE_GAP` apart are merged (`_merge_tag_gaps`), snapped to nearby blanks/scene changes (`_adjust_tags`), then merged again. Merging before snapping matters: humans fix a break end placed short by flagging a sliver of break where it really ends, and the snap drops a sliver whose ends land on one cut. `_split_lead_in` splits a leading `DO_NOT_USE` (start ≤5s, ≤60.5s) on blanks: `DO_NOT_USE` up to the first blank-delimited piece without the logo, `COMMERCIAL` after. Tags under 10s are then deleted, except at the recording's end and commercials ending by 60s: a lead-in commercial of 2–15s is real, and `post_predict` keeps a first break of any length that ends by `--show-min-len`. `--eval` applies the same merging and lead-in rewrite to its reference tags, and doesn't score the time before the log's first frame (a log can start seconds in; output there starts with the video, not at 0). A leading or trailing `DO_NOT_USE` that remains has its frames cropped whenever the log carries the tag (so in training and `--eval`, but never on a freshly flagged recording, where the model sees that junk as input), in place on the log dict passed to `load_nonpersistent` (it deletes `frames` and `tags` and shortens `duration`), so anything that writes the log back afterwards must pass a copy, as the GUI does. `COMMERCIAL` → answer 1; `DO_NOT_USE` → weight 0; frames near show/commercial boundaries are upweighted (up to 2×).

   For training, `load_persistent` caches condensed arrays next to each log as `*.data.npy` and `*.nologo.data.npy` (a synthetic variant with the logo features removed; only its windows with weight > 1 are kept, never used for validation). Caches with the wrong column count are refused, but after changing feature *values*, labels, weights or the window size you must delete the `.npy` files yourself (they hold the edge padding, and the upweight reaches `max(WINDOW_BEFORE, WINDOW_AFTER)` seconds). Nothing checks this and `--eval` builds its data fresh, so it won't show: a 90s run trained on 60s caches scored 99.05/97.58 against 99.48/98.25 rebuilt.

   So a change to what the model is fed or taught (feature columns or values, label or weight rules, the window) is not finished until all of these are dealt with:
   - the column constants and the list above match (the `assert`s in `load_nonpersistent` enforce the order);
   - the `.npy` caches under `data/` are deleted before the next training. They aren't keyed by code version, so checkouts or worktrees that share a data directory can't train with different feature code at the same time;
   - existing models are treated as invalid for a feature change. `_load_model` refuses them if the input shape changed; if only values changed they still load and quietly predict worse, `model.keras` included, so the code can't be deployed before a model trained on it is, and scores in older filenames no longer compare;
   - the published model is replaced (see Models).
4. **Model** — `neural.build_model`: dilated 1D-conv TCN with a single sigmoid output (commercial probability per second). Only `input_norm` (before the input `SpatialDropout1D`) is a BatchNorm; everything after a dropout uses LayerNorm, because a BatchNorm there learns dropout-inflated variance that is ~12% wrong at inference. Hyperparameters are module constants (`F`, `K`, `DILATIONS`, `DROPOUT`, `EPOCHS`, …). The head concatenates a learned per-channel position pool (`DepthwiseConv1D` over the whole window), softmax attention pooling and global max pooling into a `F*4`-unit `Dense` classifier. Training always runs all `EPOCHS`: warmup, then one cosine down to `MIN_LR` on the last epoch, no early stopping or `ReduceLROnPlateau`; it keeps the best-`val_weighted_accuracy` epoch, plus the latest in `<tmp model>.last.keras` (deleted unless interrupted) for resuming. SIGINT/SIGTERM stop it after the current epoch, and it then still scores and saves its best epoch so far under an ordinary-looking name.
5. **Post-processing** — `neural.post_predict` thresholds at 0.5 into tags and enforces `--break-min-len`, `--break-max-len`, `--show-min-len`. `neural.diff_tags` compares two tag lists (`-r`, `--eval`).
6. **Output** — `main.output`: `-o auto` tries the MythTV DB (`mythtv.set_breaks`) and falls back to EDL; `txt` is comskip format (`edl.py`). EDL/TXT go next to the video (the log's `filename`) unless `--output-dir`/`--output-name` say otherwise. `-o channelsdvr` (explicit only, never from `auto`) POSTs to Channels' undocumented `/dvr/files/<ID>/comskip/edit` API, finding the ID by the most trailing path components matching in `GET /dvr/files`; it is the only output that can fail the run (non-zero exit).

`-r` with several logs only rewrites a log and its output when the tags changed, and never touches an `edited` one; if a log's video no longer exists (but its directory does) and an `old/` directory sits beside the log, the log is moved there.

Recordings get transcoded `.ts` -> `.mkv` after flagging (HD ones from 29.97 to 59.94 fps), so `main._find_video` falls back from a missing `.ts` to the same-named `.mkv`. The `.mkv`'s video can start up to ~1s later than the log's (the re-encode drops the frames before the first keyframe; seen on SD upscales) while its copied audio keeps the original start. `timeline.video_lag` gets that lag from the logged stream start times, or else by lining up cuts in the log's `diff` with cuts decoded from the `.mkv`; the editor, `-r` and `upgrade_log.py` record it as `mkv_lag` (log time - `.mkv` time), and the editor and `main.output` apply it. A log's `frame_rate` is the stream's nominal rate at extraction, not a promise of even spacing; never overwrite it with the video's. `main.output` converts to frame numbers at the video's own rate: MythTV numbers the frames it actually recorded, so `mythtv._frame_for_time`/`_time_for_frame` interpolate through the recording's seek table and use the rate only past its ends; comskip `.txt` is `time*rate` with that rate in its header.

`SceneType` / `AudioSegmentLabel` in `feature_span.py` define the label integers stored in logs (`SHOW`=0, `INTRO`=1, `TRANSITION`=2, `COMMERCIAL`=3, `CREDITS`=4, `DO_NOT_USE`=5). `UNKNOWN` and `SHOW` share 0, as do several `AudioSegmentLabel` aliases.

### Model experiments

Read the results below before proposing an experiment, so nothing is run twice, and add one line for every finished one whatever its outcome (what changed, scores, verdict).

- **Score**: the `--eval` accuracy on `data/test` that training puts in the model's filename (no separate `--eval`, and no symlinks to name models). The per-window val accuracy shows trends within a run (where it peaks, whether it is still improving) but disagrees with `--eval` too often to rank models.
- **Level**: on the current test set the current recipe scores 99.29–99.42 across seeds (99.26–99.39 in filenames from before the lead-in scoring fix, which added ~0.03 to every model). The results below come from older sets, where runs scored higher, so read each line as a comparison within that line and never set a new run against it. Scores are only comparable on the same test set and `--eval` code; a filename's score dates from when it was trained or last renamed, so after the test set changes, re-score before comparing.
- **Noise**: seeds differ by about ±0.1, so run 2+ seeds and compare with baseline runs on the same data and code (the same seeds if there are any), not with the best earlier run. Call a change better only if both seeds beat both baseline seeds or its mean is at least 0.1 above the baseline mean, and worse likewise; anything else is "no measurable effect", which is the usual result and is recorded as that.
- **Mechanics**: put the change behind a module constant whose default keeps today's behaviour. `build_model` and `train` read the constants at call time, so a driver script can set them, and `PYCF_SEED` overrides `SEED`. An experiment doesn't change the defaults: adopting a result is a separate decision.
- **Data**: the directory is the split. Logs directly in `data/` train, `data/test/` validates and scores, and a log changes sets by being moved, never through a list file or a random draw. Logs added to the sets must not name the same `filename` as a training log. `data/blah` is retired: it holds unscored reference logs, and its `README.txt` lists what it held when results below were scored as test / blah. `models/old/` holds models the current code can't load or score.

Don't screen a candidate feature by how well it separates show from commercial on its own (per-log AUC): the quiet distances screened best of any feature and made blah worse. `tools/screen_feature.py` asks a narrower question with inference only: does the candidate improve a trained model's logit (logistic regression on the logit plus the candidate's window summaries, fitted on other logs, against a circularly shifted copy as chance)? It agreed with both trained outcomes it was checked against (quiet distances, cadence), but no feature that helped once trained has been through it, and it can't see a gain the model would only find when trained from scratch. `tools/ablate_eval.py` ablates input columns at inference.

Results, test / blah (on older sets; blah is retired):

- **Current head** (pos pool + attention + max, 192-unit classifier, `DROPOUT` 0.25): 99.43/98.53 on its first seed, the best on both sets then; with the full cosine 99.53/98.42 and 99.40/97.94. The same head with 144 units: mean 99.31/97.94 (2 seeds). Its predecessor (attention + max + centre second, 192 units): mean 99.39/98.50 (2 seeds).
- **LayerNorm rework** (LayerNorm after dropouts, input BN epsilon 1e-5, volume rescale, LOGO_RUN start fix, log-scaled distances, 23 → 20 features, together): ~+0.2 test, ~+0.9 blah over the old BatchNorm model. Re-estimating BN stats with dropout off instead helped test, mixed on blah. The input BN's default epsilon (1e-3) had shrunk DIFF and the volume spreads to 0.4–0.8 of unit scale.
- **Dropout**: `START_DROP` is the knob that matters: 0.05 → 99.12/98.00, 0.15 → 99.36/98.04, 0.25 → 99.39/98.50 (adopted), 0.35 → 99.26/98.32. `TCN_DROP` 0.25 → 99.16/97.90, 0.05 → 99.31/97.93, 0.1 → 99.39/97.62 vs 99.53/98.42 at 0.15 (same seed): keep 0.15. Classifier `DROPOUT` (full cosine) 0.3/0.35: mean 99.44/98.13 over 4 runs, no better than 0.25; 0.1 lost (mean 99.30/98.05, under the `EPOCHS - 5` schedule below).
- **Smaller model**: F=32 → 99.19/97.89 (2 seeds).
- **No squeeze-excite**: 99.33/98.12 vs 98.50 with it, no faster. Its gates act as near-fixed channel scales in trained models, yet training without it does worse.
- **Head analysis**: attention and max pooling each carry most of the decision; removing the centre second cost ~0.5 though alone it barely beat always-show. Attention mostly learned position (steps at fixed offsets from the edge padding, ignoring the outer ~25s) plus avoiding transitions. A quarter to a third of the classifier units never fire; activity fits in 6–9 dimensions.
- **Position-pool variants** (none matched the attention+max+centre head on blah): pool+attn+max+centre 99.24/98.31; pool+attn 96 units 99.37/98.08; whole-second dropout on the pool input 99.34/98.34 (just smears the centre peak); shared-across-channels pool 99.09/97.85; channel dropout on the pool input 99.36/98.33; L2 on the pool (1e-5, 1e-4) 99.34/98.03, 99.42/98.30 (shrinks the kernel without changing its shape). Learned pool weights are mostly wiggles over the whole window, with a centre spike in under half the channels.
- **Whole-recording sequence TCN** (branch `seq-model`): one pass per recording, ~10 min training, but well behind the window model: fixed recording starts/ends but ~40% worse mid-recording (mostly show called commercial); wider context didn't help. Gotchas: one recording per batch breaks BatchNorm and makes SpatialDropout drop a feature for the whole hour; random crops not pinned to real recording edges invent short breaks at starts/ends.
- **`padding="valid"` in the TCN**: the 121-step window shrinks to one step, so the head collapses to a single vector; lower val accuracy, never `--eval`'d.
- **Every 4th window per epoch**: no speedup at the same total updates; at half the updates, the worst of 19 models.
- **LR schedule**: `ReduceLROnPlateau` (its `min_delta` was under val noise) and early stopping ended most runs before the anneal, picking the best epoch at a high LR. The single full cosine picks its best at epochs 36–39 of 40 and scores the same as the old schedule (99.42–99.53 test, 98.11–98.22 blah); a shorter `TOTAL = EPOCHS - 5` plateau schedule was worse on blah.
- **Time-based condensing** (on main): no worse, within seed noise.
- **Frame cadence as an input** (branch `frame-timing`): no measurable effect, with or without time-based condensing.
- **Quiet distances** (`QUIET_SINCE`/`QUIET_UNTIL`, both volumes < 0.01; branch `quiet-distance`): test unchanged, blah ~0.75 worse on 2 seeds (most of it on three logs).
- **Intro/credits as plain show** (adopted): 99.52/98.14 and 99.52/98.16 vs 99.43/98.51 at weight 0.75: credits errors on test fell by two-thirds; blah's intros are still called commercial.
- **`_split_lead_in`**: fixes recording starts at no accuracy cost.
- **Window size**: 45s lost twice (99.26/97.51, 99.24/97.23); 90s 99.48/98.25, same as 60s at 1.5× the compute. The TCN's own reach is ±60s, so beyond that only the head's pooling sees more; a 90s window with dilation 16 added is untried.
- **Removing the ina columns** (ablated at inference): 99.15/97.99 with training means, 98.60/97.62 shifted, vs 99.43/98.53. The model leans on them more than on any other feature; keep them.
- **Screened only, no gain** (`screen_feature.py`): LOGO_UNTIL (R² 0.92 from existing features); distance to an ina label change, or to one near a blank/cut; current label run length; label changes per 30s; music share over ±300s; distance to the rear channels switching (lost 0.16 on blah, mostly on one log); rear/front volume ratio (reverses on over half the logs).
- **Cut patterns repeated within one recording** (screened only, current test set; `repeat`, `repeat_dist`): marks 11.2% of commercial seconds at 99.2% precision, but the model already has those right: 65 of its 762 missed commercial seconds are marked, a ceiling of +0.03, which is also the stack gain (null −0.03). Real but under seed noise, so not trained.
- **Ruled out, so don't propose them**: tuning the 0.5 threshold, averaging several models, and matching ads against stored fingerprints (audio or cut patterns): fingerprinting screened strongest, but keeping the store current would need the flagger itself.

### MythTV integration

`mythtv.py` reads DB credentials from `~/.mythtv/config.xml`; if it is missing or mysqlclient isn't installed, all MythTV functions silently no-op (so `-o auto` falls back to EDL). `main._check_mythtv_support` errors out up front if MythTV was explicitly requested (`-j`/`--chanid`/`--starttime`/`-e`/`-o mythtv`) without mysqlclient. `main._resolve_inputs` fills in the filename from `-j` or `--chanid`/`--starttime`, and `chanid`/`starttime` from `<chanid>_<starttime>.ext` (or `cf_<chanid>_<starttime>...`) filenames. `-e` makes `set_breaks` `sys.exit()` with the number of breaks and forces uncaught exceptions to exit 255: MythTV runs the command with `kMSLowExitVal`, which mangles 128–254, and 256 wraps to 0. `--rebuild`/`--queue` exec the real `mythcommflag`, as does a `-j` run whose jobqueue row has `JOB_REBUILD` set. `check_method(chanid)` respects per-channel commflag-disabled settings; when disabled, an empty break list is still output.

### comskip stand-in

`comskip.py` (`pycommflag-comskip`) replaces the comskip binary for DVRs whose only hook is running comskip (Channels DVR). It parses comskip's CLI (value options must be declared so they aren't taken as the input), maps its output options to `--output-dir`/`--output-name`, and runs a normal `-o edl` flag. Exit status mirrors comskip on Linux: 0 = breaks found, 1 = none. On any failure it deletes the partial `.edl` and execs the real comskip (`$PYCOMMFLAG_COMSKIP_REAL`, else `comskip.real` beside argv[0], not realpath'd), else exits 2. Feature logs are kept only if `$PYCOMMFLAG_LOG_DIR` is set. It must never write `<name>.log`: Channels reads comskip's log in preference to the `.edl`.

`extern/` contains vendored code (inaSpeechSegmenter, sidekit MFCC, pyannote viterbi) — avoid restyling it.
