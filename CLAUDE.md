## What this is

pycommflag flags segments of a TV recording as show/commercial (plus intro/credits/etc.) using per-frame video+audio features and a small Keras model. It is a drop-in replacement for MythTV's `mythcommflag`.

## Running

No linter config, and no pytest: the tests are plain scripts with a non-zero exit on failure (`python3 tests/test_logo_finder.py`). `test_comskip_args.py` and `test_channels.py` (a fake Channels server) need nothing else; `test_logo_finder.py` runs `logo_finder._analyze` against saved persistence maps in `tests/fixtures/`, so it needs no video -- which matters because the recordings they came from will be deleted. `fixtures/expected.json` records each one's output and, for nine of them, what a human saw in the video; two are confirmed weather alerts, the only examples of one that exist. The harness prefers a full-fidelity set in `tests/private/` (gitignored, never publish it: the maps render as readable pictures of someone's recordings) or at `PYCF_TEST_FIXTURES`, and falls back to the committed scrubbed set; each has its own `expected.json`. Regenerating a fixture means re-running the logo search over its source recording, and those get deleted over time, so prefer adding new fixtures over changing these. Packaging is `pyproject.toml` (setuptools; console scripts `pycommflag = pycommflag.__main__:main` and `pycommflag-comskip = pycommflag.comskip:main`); it is the source of truth for deps, with extras `mythtv` (mysqlclient), `yaml` (pyyaml, for `--yaml`) and `all`. `requirements.txt` mirrors it (with all extras) for the `./run.sh` + `./venv` flow; keep the two in sync. `run.sh` activates `./venv` if present, preloads jemalloc, and runs `python3 -m pycommflag` from the checkout. `pycommflag/__init__.py` deliberately imports no submodules, so tkinter/TF are only loaded by modes that need them.

```sh
./run.sh -f video.ts                 # full pipeline: extract features -> feature log -> predict -> output
./run.sh -r /tmp/cf_*.json           # re-predict from saved feature logs (fast, no video decode)
./run.sh -g cf_foo.json              # tk GUI to hand-edit tags; saves back into the feature log
./run.sh -t --data a.json b.json TEST c.json d.json   # train; files after the literal TEST token are the validation set
./run.sh --eval m1.keras m2.keras --data ...          # compare models
./run.sh --no-log -o edl -f video.ts # don't keep feature log; write .edl next to video
```

All options live in `options.get_options()` as one flat argparse parser (no subparsers, for mythcommflag CLI compatibility). The mode is derived afterwards by `options.resolve_mode` with fixed precedence: `--rebuild`/`--queue` > `-t` > `-r` > `--eval` > `-g` > flag. `--yaml FILE` overwrites any parsed option with the YAML's keys. Note `--deinterlace` stores `False` into `no_deinterlace` (deinterlacing is off by default). `main.run`'s return value is the process exit code (via `__main__.main`; `run.py` ignores it).

Without `-l` or `--no-log`, the feature log is written to `$TMPDIR/cf_<video basename>.json` and kept. When re-running `-f` against an existing log, its saved logo is reused and the logo search is skipped.

The models dir (`--models`) defaults to the checkout's `models/` (gitignored) if it exists, else `~/.keras/pycommflag` (`options._default_models_dir`, so installed copies don't point into site-packages). `neural._find_model` resolves `--model`, else `model.keras`/`model.h5` in the models dir, else `MODEL_URL` via `keras.utils.get_file`, saved as `MODEL_FNAME` in the models dir (or `options.user_models_dir()` if that isn't writable, since `get_file` would otherwise silently use `/tmp/.keras`). An existing download is deliberately left to `get_file` so it gets re-checked against `MODEL_SHA256` and re-downloaded when the published model changes; `--no-download` uses it as-is or errors. `neural._load_model` caches loaded models by realpath+mtime (each `keras.models.load_model` leaks ~5MB in TF that `clear_session` doesn't free, which added up over `-r` of many logs) and rejects models whose input shape isn't `(WINDOW_BEFORE+1+WINDOW_AFTER, FEATURE_WIDTH)`; the download is saved locally as `MODEL_FNAME`, which encodes that shape, and `MODEL_URL` is the asset of that same name in the `models` release, so after a feature/window change a new model must be uploaded under the new name and `MODEL_SHA256` updated. The GUI calls `raw_predict`, so it needs a model too. Training writes `<models dir>/pycf-<val_acc>-...keras` only if val accuracy >= 0.95.

The ina_foss audio segmenter downloads its model on first use via `keras.utils.get_file` (needs network, cached in `~/.keras/inaSpeechSegmenter`; Keras 3's `get_file` has no `datasets/` level).

Extraction and training both `os.nice()` themselves (10 and 19) because they are meant to run as background jobs.

## Architecture

Pipeline (orchestrated by `main.run`, which dispatches to the `_cmd_*` functions):

1. **Feature extraction** — `processor.process_video`: `Player` (PyAV wrapper, with error recovery in `_Recovery`) decodes; `logo_finder.search` first samples the whole video (`--logo-samples` fps) to find a static station logo (Sobel edges in the corners, ignoring overscan margins). Then frames are fed to the `VideoProc` thread (logo present, blank frame, column-mean diff; "logo present" needs 2/3 of the mask's edges lit *and* under `_LOGO_MAX_OFF_EDGES` of the box's other pixels lit, so a QR code or dense text parked over the logo doesn't count -- logs made before that rule lack it) and audio to the `AudioProc` thread (RMS of front/rear channels + `extern/ina_foss` speech/music/noise segmentation, run in chunks). Merged per-frame rows are streamed to the feature log.
2. **Feature log** (`cf_<basename>.json`, optionally `.gz`) — the central data artifact. Keys: `file_version` (currently 10), `chanid`, `starttime`, `filename` (realpath of the video), `duration`, `frame_rate`, `logo`, `frames_header`, `frames` (one row per video frame: `time, logo_present, is_blank, diff, fvol, rvol, silence, speech, music, noise`), and `tags` (list of `(SceneType value, (start_sec, end_sec))`). Tags are both the prediction output and the training labels (hand-curated via GUI). `read_feature_log`/`write_feature_log` in `processor.py` handle it; `read_feature_spans` turns frame columns into spans (used by the GUI and tag adjustment).
3. **Model input** — `neural.load_nonpersistent` turns frame rows into a float matrix. Columns are the module constants at the top of `neural.py`:
   - 0–9 (`NORMTIME`…`NOISE`): the raw frame columns, except that `FVOL`/`RVOL` are rescaled by the recording's median non-silent front volume (extraction divided by the recording's peak, which one spike skews; `HAVE_RVOL` is decided before the rescale);
   - 10–15 (`LOGO_RUN`, `HAVE_LOGO`, `HAVE_RVOL`, `PERCTIME`, `BLANK_SINCE`, `BLANK_UNTIL`): derived per-frame; the three distances (seconds since logo, since/until a blank) go through `_scale_dist` (capped at `DIST_CAP` = 300s, log-scaled), and before the first logo frame `LOGO_RUN` reads as capped, not 0;
   - 16–19 (`GENERATED_FEATURES_START`…`DIFF_MAX`): summary stats added by `condense` when it downsamples to `SUMMARY_RATE` (1/sec);
   - 20–22 (`TIMESTAMPS`, `ANSWERS`, `WEIGHTS`): bookkeeping, not model input. `FEATURE_WIDTH` = 20 is the model's input width.

   The condensed array is padded by repeating the first/last row, and `load_data_sliding_window` produces windows of `WINDOW_BEFORE + 1 + WINDOW_AFTER` (121) seconds, one per output second. Logs shorter than two windows yield `None` and are skipped. The `assert`s in `load_nonpersistent` enforce column order, so any feature change must update those constants and will invalidate existing models.

   Training labels/weights: tags are first snapped to nearby blanks/scene changes (`_adjust_tags`) and small gaps merged; then `_split_lead_in` splits a leading `DO_NOT_USE` (start ≤5s, ≤60.5s) on blanks: it stays `DO_NOT_USE` up to the first blank-delimited piece without the logo, and is `COMMERCIAL` from there on (`--eval` applies the same rewrite to its reference tags). A leading `DO_NOT_USE` that remains has its frames cropped, not just zero-weighted (as is a trailing one, even at inference). The crop is done in place on the log dict passed to `load_nonpersistent` (it deletes those `frames` and `tags` and shortens `duration`), so anything that writes the log back afterwards must pass it a copy, as the GUI does. `COMMERCIAL` → answer 1; `DO_NOT_USE` → weight 0; other non-show types → weight 0.75; frames near show/commercial boundaries are upweighted (up to 2×). For training, `load_persistent` caches condensed arrays next to each log as `*.data.npy` and `*.nologo.data.npy` (a synthetic variant with the logo features removed; training only keeps its windows with weight > 1, and it is never used for validation). Caches with the wrong column count are refused, but after changing feature *values* you must delete the `.npy` files yourself.
4. **Model** — `neural.build_model`: dilated 1D-conv TCN with a single sigmoid output (commercial probability per second). Only `input_norm` (before the input `SpatialDropout1D`) is a BatchNorm; everything after a dropout uses LayerNorm, because a BatchNorm there learns training-time (dropout-inflated) variance that is ~12% wrong at inference. Hyperparameters are module constants (`F`, `K`, `DILATIONS`, `DROPOUT`, `EPOCHS`, …); the saved filename encodes only some of them (not the dropouts or the seed). The head concatenates three summaries of the 121s window — softmax attention pooling, global max pooling, and the centre second — into a 192-unit (`F*4`) `Dense` classifier with `DROPOUT` 0.1, which scored worse than 0.25 (see Model experiments). Training monitors `val_weighted_accuracy` (early stopping, LR reduction, and best-epoch checkpoint).
5. **Post-processing** — `neural.post_predict` thresholds predictions at 0.5 into tags and enforces `--break-min-len`, `--break-max-len`, `--show-min-len`. `neural.diff_tags` compares two tag lists (used by `-r` and `--eval`).
6. **Output** — `main.output`: `-o auto` tries MythTV DB (`mythtv.set_breaks` into `recordedmarkup`) and falls back to EDL; `txt` is comskip format (`edl.py`). EDL/TXT go next to the video (the log's `filename`), with the extension replaced, unless `--output-dir`/`--output-name` say otherwise. `-o channelsdvr` (explicit only, never from `auto`) POSTs the breaks to Channels' undocumented `/dvr/files/<ID>/comskip/edit` API, finding the ID by the most trailing path components matching in `GET /dvr/files`; it is the only output that reports failure (`output` returns False, which the commands turn into a non-zero exit).

`-r` with several logs only rewrites a log and its output when the tags changed; if a log's video no longer exists and an `old/` directory sits beside the log, the log is moved there.

Recordings get transcoded `.ts` -> `.mkv` after flagging (the HD ones from 29.97 to 59.94 fps), so `main._find_video` falls back from a missing `.ts` to the same-named `.mkv` (for `-r` and `-g`), and `main.output` always converts to frame numbers (MythTV, txt) at the video's own rate. A log's `frame_rate` stays the rate its features were extracted at, which is what `load_nonpersistent` needs, so never overwrite it with the video's.

`SceneType` / `AudioSegmentLabel` enums in `feature_span.py` define label integer values stored in logs (`SHOW`=0, `INTRO`=1, `TRANSITION`=2, `COMMERCIAL`=3, `CREDITS`=4, `DO_NOT_USE`=5). Note `UNKNOWN` and `SHOW` share value 0, as do several `AudioSegmentLabel` aliases.

### Model experiments

Judge any model change by `--eval` accuracy on `data/test` and `data/blah`, run separately (the owner thinks in these %, and `good-AAAA-BBBB` links encode them), never by the training val accuracy in the filename: those disagree often (a 0.9908 model was the worst of 19 on `--eval`), and val accuracy also depends on which files follow `TEST`. Run-to-run noise for one config is about ±0.1 points on test and ±0.2 on blah, so compare 2+ seeds against the spread of earlier runs, not against the best one. `PYCF_SEED` overrides `SEED`; `build_model` and `train` read the module constants at call time, so experiments can monkeypatch them instead of editing the file.

Until 2026-10-18 `eval()` gave `diff_tags` only the COMMERCIAL tags, so predictions inside DO_NOT_USE spans (halftime, unlabelled junk) counted as errors while the accuracy denominator left them out; that cost every model ~0.02–0.13 points on test and ~0.6–1 on blah, and added noise (nfl-steelers-v-jets alone went from ~630 to ~165 wrong seconds). `good-*` links are scored with the fix, `oldgood-*` without it. 23-feature models can only be scored from a worktree at d594d94 with the same fix applied.

Results below are `--eval` accuracy, test / blah, with the fix; 2-seed means where marked.

- **Best measured config** (LayerNorm, 20 features, `START_DROP` 0.25, `TCN_DROP` 0.15, squeeze-excite, attention+max+centre head, 192-unit classifier), 2 seeds: 99.40/98.42 and 99.38/98.58 (mean 99.39/98.50). The old BatchNorm/23-feature model (6 of its 19 runs re-scored): median 99.16/97.63, so the 2026-10-14 changes (LayerNorm after dropouts, input epsilon, volume rescale, LOGO_RUN start fix, log-scaled distances, dropped columns, all trained together) gained ~0.2 on test and ~0.9 on blah, and both new runs beat every old run on blah.
- **BatchNorm after dropout** (the old model): BN running stats learned dropout-inflated variance, ~12% wrong at inference. Re-estimating the stats with dropout off helped test and was mixed on blah; LayerNorm replaced it instead. The input BN's default epsilon (1e-3) had shrunk DIFF and the volume spreads to 0.4–0.8 of unit scale (now 1e-5).
- **Dropout sweep**: `START_DROP` is the knob that matters: 0.05 → 99.12/98.00, 0.15 → 99.36/98.04 (2 seeds), 0.25 → 99.39/98.50 (2 seeds, adopted), 0.35 → 99.26/98.32 (2 seeds). `TCN_DROP` 0.25 → 99.16/97.90 and 0.05 → 99.31/97.93, no better than 0.15.
- **Smaller model**: F=32 → 99.19/97.89 (2 seeds), despite ~1.5× faster epochs.
- **No squeeze-excite**: 99.28/98.09 at `START_DROP` 0.15 and 99.33/98.12 at 0.25 (vs 98.50 with it), no faster. In trained models its gates act as near-fixed channel scales (freezing them at their means flips <1% of decisions), yet training without it does worse.
- **Head analysis** (replacing one input with its mean): attention and max pooling each carry most of the decision; the centre second alone is barely better than always saying show but removing it costs ~0.5 points. The attention head mostly learned position (sharp steps at fixed offsets from the edge padding, ignoring the outer ~25s) plus avoiding transitions (blank frames 0.52×, scene cuts 0.68×, logo seconds 1.15× their share). About 60 of the 192 classifier units never fire; activity fits in 6–7 dimensions.
- **Learned position pools** (no longer in the code; the last version is saved in `.tmp/neural.py.pos-head-2026-10-20`). Per-channel `DepthwiseConv1D(121)` over the window: learns a sharp peak at the centre second and noise elsewhere. Shared across channels (`Permute` + `Dense(1)` over time, 121 weights): a clean centre-minus-surround contrast (weights sum to ~0, positive to ±15s, negative toward the window edges). Every head with one lost on blah: per-channel pool+attn+max+centre 99.24/98.31; pool+attn+max 144 units 99.32/97.92 (2 seeds); pool+attn 96 units 99.37/98.08 (2 seeds; the closest on test, and its 96 units were all in use); with whole-second dropout on the pool input 99.34/98.34 (+max) and 99.23/98.13 (attn only; the dropout just smears the centre peak over ±10s); shared pool+attn+max 99.09/97.85. Channel dropout (`SpatialDropout1D` 0.1) on the pool input with classifier `DROPOUT` 0.1: 99.36/98.33 (1 seed); the same with `TCN_DROP` 0.1: 99.21/97.73 (1 seed), but a second unscored `TCN_DROP` 0.15 run (…1792460560) is about as bad as it on the logs it loses (nbc-news, limitless, paradise), so that gap may be mostly seed luck; with classifier `DROPOUT` 0.15 (`TCN_DROP` 0.15): 99.26/97.97 (1 seed). Over its 7 scored variants this head has never matched the best config on blah. Its pool weights are still mostly wiggles spread over the whole window (±15s holds 30% of the weight, 26% if uniform); 21 of 48 channels have a centre spike and 14 an edge spike. Replacing each head input with its mean flips 3.2% (pos), 5.2% (attn) and 1.2% (max) of decisions on 9 logs, and the max one slightly *raised* accuracy there; 33 of 144 classifier units never fire, 9 dimensions hold 90% of their variance.
- **Whole-recording sequence TCN** (branch `seq-model`, not merged, old scoring): one pass per recording and ~10 min training, but well behind the window model. It fixed recording starts/ends but was ~40% worse mid-recording (mostly show called commercial); wider context didn't help. Gotchas: one recording per batch breaks BatchNorm (per-recording statistics; validation collapses) and makes SpatialDropout drop a feature for the whole hour; random crops not pinned to the real recording edges invent short breaks at starts/ends.
- **`padding="valid"` in the TCN**: with K=5 and dilations 1,2,4,8 the 121-step window shrinks to one step, so the head collapses to a single vector; consistently lower val accuracy, never `--eval`'d.
- **Training on every 4th window per epoch**: at the same total updates it scored like normal runs, so no speedup; at half the updates it was the worst of 19.
- **The lead-in labelling (`_split_lead_in`)** did not cost accuracy: it fixes recording starts, and lead-ins are a tiny share of test+blah.
- **Classifier 144 units** (`F*3`; the best runs used 192), 1 seed each, probably both with the `TOTAL = EPOCHS - 5` LR schedule: classifier `DROPOUT` 0.25 → 99.26/98.01, 0.2 → 99.27/98.27, 0.1 → 99.30/98.33. Dropping the classifier dropout to 0.1 recovered most of the blah loss. 192 units with 0.1 (and `TOTAL = EPOCHS - 5`), 2 seeds: 99.31/97.95 and 99.28/98.15 (mean 99.30/98.05), well behind 0.25 with the old schedule. No run since the `TOTAL = EPOCHS - 5` schedule went in has reached 98.42 on blah, so that schedule is a suspect.
- **Not tried yet**: a smaller window (the attention ignoring the outer ~25s is largely a padding effect, and the window grew 15→30→60 with gains each time).
- Not wanted by the owner: tuning the 0.5 decision threshold, and averaging several models' predictions.

### MythTV integration

`mythtv.py` reads DB credentials from `~/.mythtv/config.xml`; if it is missing or mysqlclient isn't installed, all MythTV functions silently no-op (so `-o auto` falls back to EDL). `main._check_mythtv_support` errors out up front if MythTV was explicitly requested (`-j`/`--chanid`/`--starttime`/`-e`/`-o mythtv`) without mysqlclient. `main._resolve_inputs` fills in whatever is missing: filename from `-j` or from `--chanid`/`--starttime`, and `chanid`/`starttime` from `<chanid>_<starttime>.ext` (or `cf_<chanid>_<starttime>...`) filenames. `-j JOBID` updates job-queue status; `-e` makes `set_breaks` `sys.exit()` with the number of breaks (and forces uncaught exceptions to exit 255: MythTV runs the command with `kMSLowExitVal`, which mangles 128–254, and 256 wraps to 0, so 255 is the only error status it sees as a failure). `--rebuild`/`--queue` just exec the real `mythcommflag`, and so does a `-j` flag run whose jobqueue row has `JOB_REBUILD` set (queued by `mythcommflag --queue --rebuild`; `main.run` execs `mythcommflag -j N --noprogress`). `check_method(chanid)` respects per-channel commflag-disabled settings; when disabled, an empty break list is still output. `mythtv.get_breaks`/`processor.guess_external_breaks` can read existing breaks back out of MythTV.

### comskip stand-in

`comskip.py` (`pycommflag-comskip`) replaces the comskip binary for DVRs whose only hook is running comskip (Channels DVR). It parses comskip's CLI (value options must be declared so they aren't taken as the input; the rest are ignored), maps `--output`/`--output-filename`/positional outdir to `--output-dir`/`--output-name`, and runs a normal `-o edl` flag. Exit status mirrors comskip on Linux: 0 = breaks found, 1 = none. On any failure it deletes the partial `.edl` and execs the real comskip (`$PYCOMMFLAG_COMSKIP_REAL`, else `comskip.real` beside argv[0], not realpath'd), else exits 2. Feature logs are kept only if `$PYCOMMFLAG_LOG_DIR` is set. It must never write `<name>.log`: Channels reads comskip's log in preference to the `.edl`.

`extern/` contains vendored code (inaSpeechSegmenter, sidekit MFCC, pyannote viterbi) — avoid restyling it.
